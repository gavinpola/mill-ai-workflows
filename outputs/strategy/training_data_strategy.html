01 - The key insight

Mill isn't solving general food recognition

Academic benchmarks target open-domain food classification across global cuisines. Mill is solving a dramatically simpler problem: classify waste in a controlled environment with multi-modal data and known menu constraints.

03 - Human-in-the-loop

Confidence-based routing

Not all predictions need human review. Route based on model confidence to minimize labeling load while capturing exactly the training examples we need most.

> 0.90
AUTO-ACCEPT Log for spot-check, no human review required
~65%
0.70 - 0.90
SAMPLE 10% random sample sent to human review
~25%
< 0.70
FULL REVIEW Every prediction reviewed by human labeler
~10%

Why this works

Low-confidence predictions are exactly the training examples we need most. The system automatically surfaces the hardest cases for labeling. Each week, the model improves on exactly its failure modes - then fewer predictions fall into the low-confidence bucket.

Active Learning Strategies

Primary
Uncertainty Sampling

Score all predictions by entropy. Top 20% uncertain predictions go to human review queue. Targets exactly where the model is weakest.

Category-Aware
Class Balancing

Track accuracy per food category. Oversample from low-accuracy categories. Prevents model from ignoring rare foods.

Multi-Modal
Disagreement Detection

When vision says "chicken" but weight signature says "bread" → flag for review. Multi-modal disagreement signals difficult cases.

Novel
Unknown Detection

When model encounters food it's never seen, flag as "unknown." Route to expert for new category creation.

04 - The hard problem

Partial food classification

A model trained on Food-101 achieves 90%+ accuracy on whole foods but drops to 60-70% on partial foods. This is the gap Mill must close - and multi-modal fusion is how we do it.

Modality What It Captures Partial Food Benefit
Vision (6-angle) Color, texture, shape Some angles preserve recognizable features
Weight signature Density, mass, impact dynamics Density unchanged by partial consumption
Before/after diff What was added to the bin Volume change helps estimate quantity
Menu context What's possible Constrains classification space

Sensor Fusion Training

Train the model to use ALL modalities. When uncertain visually, trust weight signature. When weight suggests chicken but vision says bread, flag for review.

07 - How ML Training Actually Works

From raw data to deployed model

Understanding the mechanics: how the model learns, what happens on the chip during inference, and how data flows between edge devices and cloud.

The Training Loop

Training a neural network is an iterative optimization process. For each batch of images, the model makes predictions, calculates error, and adjusts its weights to improve.

1
Forward Pass
Images flow through network layers → model outputs predictions
→
2
Loss Calculation
Compare predictions to true labels → compute error score
→
3
Backpropagation
Calculate gradients → how much each weight contributed to error
→
4
Optimizer Step
Update weights to reduce error → model improves slightly
→
5
Repeat
Next batch of images → thousands of iterations until convergence
↺
Batch size: 32-64 images
Epochs: 50-100 passes
Training time: 4-8 hours
Total iterations: ~50,000-100,000

Transfer Learning: Standing on Giants' Shoulders

We don't train from scratch. We start with a model pre-trained on millions of images, then fine-tune it for our specific task. This dramatically reduces data requirements.

Training from scratch would require 10x more data and compute. Transfer learning lets us achieve 80% accuracy with just 15,000 labeled images instead of 150,000+.

Weight Signal Processing
How load cell data becomes features

Raw signal → 100Hz sampling → 0.5s window

  • Statistical: mean, std, peak, skewness
  • FFT: dominant frequency, power spectrum
  • Output: 128-dimensional feature vector
Why Intermediate Fusion
Best of both worlds

Each modality learns independently, then fusion layer learns trust weighting:

  • Vision confident → trust vision
  • Vision uncertain → weight signal votes higher
  • Disagreement → flag for human review

What Happens On-Chip (Jetson Orin NX)

When food is dropped into the bin, here's exactly what happens on the edge device - from weight trigger to classification result in under 600ms.

0 ms

Weight Trigger

Load cells detect >50g change. System triggers burst capture mode.

0-500 ms

Image Capture

6-angle Kaleidoscope captures 10 fps burst. Before/after images stored locally.

500-520 ms

Preprocessing

Resize images to 224x224. Normalize pixel values. Extract weight features from signal.

520-550 ms

Inference

Forward pass through TensorRT engine. INT8 quantized model (~50MB). Output: class probabilities.

550-560 ms

Post-Processing

Apply menu constraints (mask invalid classes). Compare vision + weight predictions. Flag disagreements.

560 ms

Result

Classification + confidence score. Decision: auto-accept, sample, or full review.

Weekly Retraining Pipeline

Every Sunday night, the model retrains on new labeled data from the past week. By Monday morning, improved models roll out to the fleet.

Sunday 6pm
Data Aggregation
Pull human-labeled images from past week. Combine with existing training set. Balance classes.
Sunday 7pm
Dataset Preparation
Split 80/10/10 (train/val/test). Apply augmentation pipeline. Convert to TFRecord.
Sunday 8pm - 2am
Training
4x A100 GPUs. Fine-tune from previous week's model. ~50 epochs, 6 hours.
Sunday 2am - 4am
Evaluation
Run on held-out test set. Compare to previous version. Flag if accuracy regressed.
Sunday 4am - 5am
Optimization
Export to ONNX. TensorRT optimization. INT8 calibration. Package for OTA.
Monday 6am
Staged Rollout
Deploy to 5% fleet (canary). Monitor 4 hours. If stable → 25% → 100%.
GPU cost: ~$150/week
Storage: ~$50/month
Total: ~$800/month

OTA Model Updates

Safe, atomic updates with automatic rollback. New models download in the background and swap in without interrupting inference.

1

New model ready

Cloud packages signed model (~50MB) with hash verification

2

Download in background

Device downloads while inference continues uninterrupted

3

Verify signature + hash

Cryptographic verification prevents tampered models

4

Atomic swap

Old model → backup partition. New model → active partition.

5

Post-update validation

Run inference on test images. If fails → automatic rollback to previous version.

6

Report success

Device confirms update. Cloud tracks fleet-wide deployment status.

Safety Features

Dual partitions: Always have working fallback. Signature verification: Prevent tampered models. Post-update validation: Test before committing. Automatic rollback: If accuracy drops significantly.
